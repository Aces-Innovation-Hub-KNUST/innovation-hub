# ACES Innovation Hub

The ACES Innovation Hub supports student-led innovation and project development in association with the Association of Computer Engineering Students (ACES), Kwame Nkrumah University of Science and Technology (KNUST).

This repository is the Hub's shared home for project-pipeline guidance, software and hackathon activities, reusable templates, and learning resources. It is an organizational resource—not a personal portfolio or a replacement for the Hub's external website.

> **Planning status:** Activities and dates described for the 2026/2027 academic year are plans, not confirmation that an event has taken place. Updates should distinguish planned, ongoing, and completed work.

## The project pipeline

The Hub supports projects through **Idea → Prototype → Funding**. Projects enter through a one-page idea intake, are screened, and may proceed through incubation, mentorship, milestone planning, and monthly check-ins. Teams can work toward a showcase or demo and pursue suitable grants, sponsorships, competitions, or other funding opportunities.

Screening should consider the real problem, feasibility, the team, and a clear next step. See [the project pipeline guide](docs/hub/project-pipeline.md) for what to capture at each stage.

## Software development activities

The Software & Hackathons board responsibility covers software hackathons, software skill sprints, and the Hub GitHub organization. Flagship events are delivered by volunteer organizing committees led by the relevant board member; responsibility does not mean one person performs every task.

Planned skill-sprint areas include Git/Linux, microcontrollers, Web/APIs, and Embedded C. The planned Software Hackathon is **2–4 April 2027**. Details and planning status are in [the skill-sprints guide](docs/skill-sprints/README.md) and [the Software Hackathon guide](docs/hackathons/software-hackathon.md).

## How students can contribute

Beginners are welcome. Contributions can include project work, documentation, templates, learning resources, issue reports, and small improvements—no prior contribution history is required.

1. Clone this repository.
2. Create a branch for your change.
3. Make focused changes and check the relevant documentation.
4. Commit your changes with a clear message.
5. Push your branch to your fork or the repository, as access permits.
6. Open a pull request and explain what changed and why.
7. Respond to review feedback.
8. A maintainer reviews and merges approved changes.

Read [CONTRIBUTING.md](CONTRIBUTING.md) for a beginner-friendly workflow and review expectations.

## How projects move through the pipeline

Use the [project idea template](templates/project-idea.md) to describe an idea. Screening is a decision point, not a promise of acceptance or funding. If a project proceeds, keep its stage, milestones, check-ins, blockers, and resource needs current using the templates in [`templates/`](templates/). Only document real projects after they have been approved or formally entered into the pipeline.

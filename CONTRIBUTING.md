# Contributing

Students at every experience level are welcome to contribute. Helpful contributions include project work, documentation, templates, learning resources, issue reports, and small corrections.

## Workflow

1. **Clone** the repository, or fork it if you do not have write access.
2. **Create a branch** with a short, descriptive name, such as `docs/pipeline-guide`.
3. **Make focused changes.** Follow existing terminology and keep planned activities clearly distinct from completed work.
4. **Verify your changes.** Check Markdown links, spelling, dates, and any project-specific tests or instructions.
5. **Commit** with a clear message describing the change.
6. **Push** your branch to your fork or the repository, as access permits.
7. **Open a pull request.** Explain what changed, why, how you verified it, and whether an existing project is affected.
8. **Review and merge.** Respond to review feedback; an authorized maintainer merges approved changes.

## Project contributions

Use the [project idea template](templates/project-idea.md) when proposing a project. A proposal is not automatically accepted into incubation or promised funding. Follow the [project pipeline](docs/hub/project-pipeline.md) and use the matching templates as the project advances.

## Good contribution practices

- Make changes that are understandable to the next student team.
- Do not add invented names, project outcomes, sponsors, contacts, or event details.
- Do not commit passwords, API keys, private credentials, or sensitive personal information.
- Keep documentation and project status current when a change affects them.
- Follow the [Code of Conduct](CODE_OF_CONDUCT.md) and [security guidance](SECURITY.md).

If you are unsure where a contribution belongs, open an issue describing the question before making a large change.
